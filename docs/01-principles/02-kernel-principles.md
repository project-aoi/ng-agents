# 原子内核与编排架构原则（薄内核 $\times$ 可编程协同准则）

> [!IMPORTANT]
> 本层文档属于**第一层：产品与架构设计原则（最高准则）**。它定义了 `ng-agents` 为什么收敛为「1 条异步信封流 + 6 个封闭原语 + `Cell` 容器」，以及哪些逻辑必须写进确定性内核代码、哪些逻辑必须留给角色提示词与 `SKILL.md`。

---

## 一、核心架构哲学：薄内核守确定性硬底线，厚编排靠原语与提示词生长

许多 Agent 系统要么把业务流程写死成几百行刚性状态机（换个场景就卡死），要么把几个角色拉在一个大群聊里自由发挥（丢消息、互相踩目录、刷爆账单）。

`ng-agents` 的架构准则是严格切分**「机制（Mechanism）」**与**「策略（Policy）」**：
- **内核只做确定性机制**：消息幂等排队与串行认领、工作树单写者互斥、一次性分身排空交卷自关、乐观锁版本校验、5 锚点悬空检测、权限单调收紧与预算硬护栏——凡是靠提示词管不住的并发竞态与安全底线，100% 由内核代码在 SQLite 事务内兜底。
- **编排全走柔性策略**：先调研还是先改码、分几个阶段门控、公共阻塞由谁派单修、结项前如何复盘偏好，不在内核写死任何业务分支，全部由各 `Cell` 角色提示词（`presets`）与按需加载的 `SKILL.md` 组合基础原语完成。

---

## 二、最小完备底座：1 条信封流 + 6 个数据面原语 + 1 个控制面容器

全系统底层不再堆砌定制业务组件，收敛为职责完全封闭的 **6 + 1 模块**：

| 模块 | 层级 | 封闭职责（管什么） | 边界红线（绝不越界管什么） |
| :--- | :--- | :--- | :--- |
| **`Envelope`** | 通信契约 | 统一异步消息信封（幂等 `id`、验签身份 `principalId`、目标纪元 `expectedEpoch`、唤醒/静默投递模式） | 不夹带可变内存引用，跨进程/跨重启完全可序列化重放 |
| **① `Channel`** | 数据面原语 | 外部协议（IM / Webhook / UI）验签入站、渠道能力如实声明、幂等外发与专注期免打扰缓冲（`buffered_dnd`） | 只管对人/对外部系统的进出通道；**跨 `Cell` 内部协作直走同库 `Inbox`，绝不绕外部 `Channel`** |
| **② `Inbox`** | 数据面原语 | SQLite WAL 队列、原生 `deliverAt / cron / idleSec` 定时唤醒、按订阅窗口攒批（`coalesceMs`）、单 `Cell` 串行租约锁、跑题退回（`handback`）与实时控制旁路（`cancel / pause / resume / steer`） | 不解析业务语义，只保证投递不丢、认领不重、控制指令绕开普通排队锁秒级生效 |
| **③ `Context`** | 数据面原语 | 物理分三层：① 业务状态（`cell_state`）与带 `expectedVersion` 乐观锁的交付物 `Artifact`（支持创建与局部 `patch`）；② 只追加 `evidence`（含溢出 `resources`、冻结前缀 `hydrate` 与全域 `FTS5` 检索）；③ `SKILL.md` 与带作用域的长期偏好 | 不允许上下文压缩误删结构化状态或 `Artifact`；已内联进系统提示词的技能不再重复挂入待读索引 |
| **④ `Loop`** | 数据面原语 | 单次有界执行（`Run`）：统一支持 **`llm` 大模型推理**（API 或持久化复用会话的本地 CLI Agent，严格区分 `strong / fast` 档位）与 **`code` 零 Token 确定性处理器**；步数触顶与模型拒答显式返回 `step_limit / refused` | 平时休眠零开销（Sleep-by-Default）；绝不将步数截断或拒答伪装成正常 `completed` |
| **⑤ `Workspace`** | 数据面原语 | 执行目录句柄、声明式读写模式（`cwdMode: "read" \| "write"`）与跨轮次存活的异步长进程句柄（`startJob` + `cancelling` 退净确认） | 不暗建假仓库、不篡改宿主 `$HOME`、关闭 `Cell` 时只回收运行态进程/容器，绝不删宿主机目录 |
| **⑥ `Gate`** | 数据面原语 | 单调权限收紧（`child ⊆ parent`）、密钥白名单代理、绑定 `epoch` 与草稿 `version` 的挂起审批卡（`defer`）、监督树增量 + 缓存加权双账本预算护栏 | 普通内部协作免打扰放行；对外向他人发消息与超预算续费强制锁死人类 `owner` |
| **⑦ `Cell`** | 控制面容器 | 将 6 个原语拼装为带单调递增 `epoch` 与 `parentId` 监督树的运行单元：承载 6 套角色预设（`inline / project / worker / watcher / sensor / hub`）、工作树队列调度与级联回收 | 不做运行期“半路热搬家（沙箱过户）”；常驻等待/停靠容器不挤占活跃执行并发配额 |

## 三、六条核心架构准则

### `P-KERN-1`：上下文上浮归持久 `Project`，重活下沉归短命 `Worker`（严禁单会话黑盒淤积）
1. **禁止把跨阶段长任务闷在单个超长 CLI 会话里跑到底**：否则外界对中间进展彻底失明，中途插入并行需求无法拆分，且超长上下文必然导致注意力退化与自我审查偏见。
2. **`Project` 握住接力棒，`Worker` 跑完一棒排空即关**：
   - **`project` `Cell` 持久存活**：只做轻量规划与质检，把目标、动作球权账本、分支/链接等环境事实（`relay:context`）与版本化 `Artifact` 透明保存在项目层；
   - **`worker` `Cell` 一次性执行**：承接明确界定的一棒任务（调研、改码、跑测试、独立终审），完工后经内核**单事务排空检查（`Drain-then-Close`）**确认无未读追单、无未关下级后，投递唯一幂等回执 `${cellId}:${epoch}:cell.result` 并自动关闭。

### `P-KERN-2`：异步事件走队列，UI 简单交互直走同步事务
- 外部入站消息、定时触发、后台 `Job` 完结与跨 `Cell` 汇报一律走 `Inbox` 异步信封队列；
- 人类在工作台勾选速办项、保存手改草稿、点击批准/推迟卡片、切换项目暂停/激活状态，直接调用服务端同步事务接口毫秒级落盘返回（需唤醒下游协调器时在事务内顺手投递一条信封），**绝不为了打个勾去空转一轮大模型**。

### `P-KERN-3`：外部监听看“当前事实与持久历史”（Level-Triggered 优于 Edge-Triggered）
- 等待 MR 合入、CI 全绿、目录就绪或同事回信时，绝不依赖“恰好在事件发生前那一毫秒挂上了内存回调”的边沿巧合；
- 入站渠道消息先持久化落库可查；`watcher / sensor` 每次唤醒**第一步永远是直接核查当前真实状态或持久历史记录**——无论目标事件发生在监听启动前 3 秒还是启动后 3 小时，行为完全一致、零漏检。

### `P-KERN-4`：严格保持前缀不变保缓存，执行算力按 `0-Token / fast / strong` 三级分流
1. **Prefix-Invariant Context**：系统提示词不塞随时间跳变的动态噪音；长期偏好在立项前落库，使持久 `Cell` 会话生命周期内系统前缀稳定不变，保持 **95%+ Prompt Cache 命中率**；多轮状态变化仅作为尾部动态注记追加。
2. **算力精准匹配任务复杂度**：
   - **零 Token 确定性层（`code` / 脚本探针）**：常态 CI/状态轮询、简单规则匹配、固定回信等待（`await_reply`），等待与未就绪轮询消耗 **0 Token**；
   - **轻量快速层（`modelTier: "fast"`）**：异常状态研判（如区分 CI 自动重跑中还是终态失败）、轻量路由与格式整理，必须映射至轻量模型或低推理档（严禁退化为旗舰 `@xhigh` 空烧预算）；
   - **主力深度层（`modelTier: "strong"`）**：复杂架构规划、跨仓源码深挖、核心编码与独立源码终审。

### `P-KERN-5`：长交付物走版本化共享 `Artifact`（创建 + 局部补丁），父子之间只传摘要与指针
- 上万字的调研报告、架构方案与终审结论必须存入共享版本化 `Artifact`，父子 `Cell` 消息传递只携带 `artifactId`、版本号与核心结论摘要，绝不在多棒对话之间反复拷贝全文；
- 后续分身补充证据或修订章节时，优先通过带 `expectedVersion` 的局部修订（`patch_artifact`）增量升版，且未显式改名时自动保留原报告标题，避免数十次分页重读整篇大文档。

### `P-KERN-6`：生成与终审上下文物理隔离（Clean-Room Verification）
- 涉及重要代码合入、复杂重构或高风险方案交付时，协调器应派生一个**全新的只读终审 `worker`** 对照硬性检查清单独立核验真实 `git diff` 与门禁回执；
- 终审分身不继承编写者的思维包袱，发现边界缺陷如实签发分级问题单（拒绝橡皮图章式盲签 `PASS`）。

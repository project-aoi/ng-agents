# 安全边界、宿主现场与算力治理准则

> [!IMPORTANT]
> 本层文档属于**第一层：产品与架构设计原则（最高准则）**。`ng-agents` 默认运行在工程师真实的开发机上、复用真实凭据与真实代码目录——因此现场保护、读写互斥、身份隔离与算力账本是绝不可妥协的工程生命线。

---

## 一、宿主目录与工作树安全边界

### `P-SAFE-1`：回归真实宿主环境，零暗箱目录代管、零宿主目录误删
1. **直接在主人指定的真实路径（`cwd`）上工作**：默认保留宿主机真实的 `$HOME`、SSH 配置、Git 身份与本地 CLI 登录态及自定义技能（如 `/ship-mr`），不暗建空目录假 `$HOME`、不私自创建假 Git 仓库。
2. **运行态回收与文件系统绝对解耦**：`closeCell` 或取消任务时，内核**只回收进程与显式容器运行态**（递增 `epoch`、中断在途 `Run`、终止后台 `Job` 进程树并确认退净、销毁显式容器隔离实例），**在任何代码路径下绝对禁止对宿主机工作目录执行 `rmSync`、自动重置分支或乱打快照提交**。

### `P-SAFE-2`：声明式工作树读写仲裁（同树单写排队 $\times$ 多读零锁并行与沙箱护栏）
1. **单写者内核排队（`cwdMode: "write"`）**：
   - 规划层与协调器无需手搓分布式锁或猜锁重试；内核 `Dispatcher` 按规范化工作树根（`git.toplevel(cwd) ?? realpath(cwd)`）维护严格的单写者 FIFO 队列；
   - 同一棵工作树下的根目录与子目录共享同一写锁，而不同独立 `git worktree` 之间天然并行；前序写任务的 `Run` 及其名下后台 `Job`（含 `cancelling` 过渡态）彻底退净后，才放行下一位写者；任务调用 `wait` 进入休眠且无活跃 `Job` 时立即自动让出写槽位，杜绝死锁。
2. **多读者零排队并行与物理防误写（`cwdMode: "read"`）**：
   - 声明只读的协调器、评审、调研与终审分身**零排队全速并行**；
   - CLI 适配层需为 `cwdMode: "read"` 分身挂载底层操作系统级只读保护，**物理阻断修改本地工作树文件与索引**，但同时明确放行合理的只读工程动作：允许读取跨目录源码、允许只读 `git fetch` 更新远端跟踪引用与部分克隆（partial clone）按需拉取对象、允许 SSH 远端只读查询、允许在系统临时目录（`/tmp`）存放计算中间态。

### `P-SAFE-3`：主人现场神圣不可侵犯与全角色不可逆操作红线
1. **动刀前必验现场**：任何 `cwdMode: "write"` 分身在修改第一行文件、切分支、rebase 或提交前，必须先执行 `git status --short --branch`：
   - 若撞见交接说明之外的**未提交改动、陌生分支、合并冲突锁或非自身引入的公共 CI 挂死**，**绝对禁止擅自执行 `git reset --hard`、`git clean`、`git checkout -f`、`git restore` 或 `git stash`**；
   - 必须立即将现场详情发往树根 `inbox:desk` 并调用 `wait(waitingFor: "inbox:desk")` 休眠让出目录槽位，由 `desk` 查明是前序分身遗留、公共阻塞（单开 1 个独立修复者）还是主人正在手写代码（弹阻塞升级卡交主人定夺）。
2. **全角色不可逆操作禁令**：未经人类通过审批卡针对该次具体操作明确点确认，任何角色严禁强推覆盖（`push --force`）、直推或删除受保护主干、删除远端分支/Tag/MR、触碰生产数据库或线上配置、公开发布包或对外群发不可撤回写请求。

## 二、权限、身份与版本并发护栏

### `P-SAFE-4`：单调权限收紧（`child ⊆ parent`）与双身份硬隔离（`owner` vs `agent:*`）
1. **权限沿监督树单调递减**：派生子 `Cell` 时，`Gate.attenuate` 强制保证工具集、可投递地址集与密钥白名单满足 `child ⊆ parent`，且剩余派生深度 `maxDepth` 逐层递减归零即止。
2. **外部主 Agent 编排同权但绝不冒充主人**：
   - 外部主 Agent 通过独立凭证以一等身份 `agent:<id>` 接入控制面，拥有立项、派单、带话、暂停/恢复/取消、勾选人类已完成动作与代办普通计划卡片的完整编排权；
   - **两条人类专属红线（`ownerOnly: true`）在内核全入口硬拦截**：**① 向他人或外部群聊发出消息（`channel:*` 非主人地址）**、**② 预算耗尽熔断后的加额续费（`budget_exhausted`）**，任何 `agent:*` 凭证调用一律拒绝，必须由人类 `owner` 本人在工作台界面点击放行。

### `P-SAFE-5`：双版本号精确防呆（`Cell.epoch` 防诈尸 + `Artifact.version` 防覆盖与盲发）
1. **`Cell.epoch`**：取消或关闭 `Cell` 时原子递增纪元号；迟到的旧定时器、旧子分身回执或残留后台 `Job` 结果因 `expectedEpoch` 不匹配被内核静默丢弃，彻底杜绝已关项目“诈尸”。
2. **`Artifact.version`**：
   - 跨 `Cell` 修订已有 `Artifact` 强制校验读取时的 `expectedVersion`；若期间人类已在专注区手动改稿提交（`updatedBy: "human"`），后台旧基线写入绝不覆盖手写稿，而是安全旁路暂存（`park`）供参考；
   - 人类点击审批卡确认外发时，同步事务强制校验点击瞬间所见的 `seenArtifactVersion`——若后台刚刷新了新版初稿，立即提示重审，绝不盲发未看过的新内容。

## 三、算力账本、防悬空与宿主电源韧性

### `P-SAFE-6`：5 锚点球权不变量与单次防自激停滞巡检
- 任何处于活跃态（`lifecycle === "active"` 且未 `paused`）的项目及其子树，在任意时刻必须至少拥有以下 **5 类推进锚点**之一：① 在跑的非巡检 `Run / Job` 或待领唤醒消息（`@Agent`）；② 活跃外部监听 `watches / watcher` 或未到期定时调度（`@Waiting: external`）；③ 目标未关闭的内部等待记录（`@Waiting: internal`）；④ 待批卡片或未完结的 `@Human` 动作（`@Human`）；⑤ 已显式停靠/暂停/完结。
- 一旦 5 锚皆空掉入悬空态（`stalled`），`Radar` 立即标红，且内核仅投递**唯一一次** `kernel.stalled_check` 唤醒（巡检消息及其触发的 `Run` 本身不计入有效锚点，彻底杜绝空转死循环烧钱）。

### `P-SAFE-7`：零丢信封的精准增量预算护栏与宿主休眠保护
1. **认领前预检，零吞入站消息**：预算门禁必须在消费收件箱信封、推进状态化 CLI 会话之前先行拦截——超限时入站 `cell.result` 等信封必须保留在 `pending` 队列中，绝不允许因毫秒级 `budget_stopped` 短路而把子分身交回的成果吞进黑洞；对所有子任务已完结、仅差最后一步调 `finish_project` 收尾的协调器预留小额收尾缓冲。
2. **真实单轮增量与缓存加权计量**：对持久化 `resume` 的 CLI 会话，必须用 `当前累计用量 - 上轮已结算用量` 计算**真实单轮增量**（杜绝 $O(K^2)$ 重复累加虚增），并将高命中率的前缀缓存输入按实际折扣权重计入预算账本。
3. **祖先链一键联调续费**：当子项目与上层主台同时触及预算硬上限时，人类在界面点击一次「继续」，`Gate` 沿祖先链幂等一次性补齐所有卡住层级的额度，绝不背靠背连弹多张预算卡。
4. **宿主电源守护与时钟跳变续租**：后台存在活跃 `Run` 或在途任务时，在支持的宿主系统（如 macOS `caffeinate -i`）自动持有防空闲休眠断言；当笔记本合盖物理休眠唤醒、检测到挂钟跳变远大于单调时钟推进时，**必须先顺延所有活跃认领租约（Lease）再执行过期回收扫描**，防止将仍在正常运行的 CLI 进程误判超时重发。

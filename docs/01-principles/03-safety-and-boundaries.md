# 安全边界、宿主现场与算力治理准则

> [!IMPORTANT]
> 本层文档属于**第一层：产品与架构设计原则（最高准则）**。`ng-agents` 默认运行在工程师真实的开发机上、复用真实凭据与真实代码目录——因此现场保护、目录协同、身份隔离与算力账本是绝不可妥协的工程生命线。

---

## 一、宿主目录与工作树安全边界

### `P-SAFE-1`：回归真实宿主环境，零暗箱目录代管、零宿主目录误删
1. **直接在主人指定的真实路径（`cwd`）上工作**：默认保留宿主机真实的 `$HOME`、SSH 配置、Git 身份与本地 CLI 登录态及自定义技能（如 `/ship-mr`），不暗建空目录假 `$HOME`、不私自创建假 Git 仓库。
2. **运行态回收与文件系统绝对解耦**：`closeCell` 或取消任务时，内核**只回收进程与显式容器运行态**（递增 `epoch`、中断在途 `Run`、终止后台 `Job` 进程树并确认退净、销毁显式容器隔离实例），**在任何代码路径下绝对禁止对宿主机工作目录执行 `rmSync`、自动重置分支或乱打快照提交**。

### `P-SAFE-2`：目录协同由 AI 决定，内核只亮活跃目录事实（不排队、不加锁）
主人随时可能直接让某个分身「顺手把这行修了」，待命的 `worker` 随时可能被消息唤醒：事先声明读写并在内核排队，要么挡住主人的直接指令，要么让排队者带着过时的假设开工；而锁也代替不了判断——两个分身改不同文件可以并行，改同一处即使排队也会在语义上互相覆盖。因此：
1. **内核不为目录排队或加锁**：每个被派发的 `Cell` 只受常规并发上限（`maxConcurrentRuns`）约束，立即启动；同一工作树里的两个 `worker` 会同时改动文件，除非协调器事先安排。`CellSpec.cwdMode` 只为兼容旧规格而保留在存储中，内核任何路径都不再读取它；宿主命令与后台任务经 Workspace 执行。各角色「只看不改」的边界全部来自提示词契约：`desk`、`project`、`hub`、`checker`、`reply_watcher` 的角色提示词各自声明不改磁盘；`sensor` 信源由提示词红线 `SOURCE_RED_LINES`（只看：不改、不删、不推、不发）约束，且它默认在内核为它单独建的私有目录 `<dataDir>/cells/<cellId>` 里执行检查命令（预设 `inheritCwd: false`，不继承项目目录），工具集里没有通信工具（只能 `no_hit / report_hit`）——内核不对任何角色做文件系统级只读拦截。
2. **内核亮出实时事实 `[active workspaces]`**：哪些 `Cell` 此刻有在跑的 `Run` 或运行中的后台 `Job`、各在哪棵工作树（以 `git rev-parse --show-toplevel` 归一，非仓库目录取真实路径；同一工作树的子目录合并，不同的 `git worktree` 各算一棵）、属于哪个项目、在做什么——被关闭 `Cell` 的 `Job` 在进程组确认退净前仍计入。这份事实挂在每次唤醒的动态尾部：协调器（`desk / project / hub`）看到所有工作树，叶节点只看到与自己同一工作树里的其他活跃者；外部主 Agent 经控制面 `list_workspaces`、主人经 `Agents` 视图的同目录高亮看到同一份事实。它是信息，不是锁。
3. **协调器决定谁在哪干**（提示词契约）：派单前看 `[active workspaces]` 与自己的项目笔记——
   - 本项目已有 `worker` 正在该仓库做相关的事：把新要求发给它（`send_message`），或等它本轮结束再派下一棒；
   - 有人（本项目或其他项目）正在该仓库改代码而新任务只需查阅：照常派出，指令写明「当前有人在这个仓库改代码：只做查阅，不要改文件、不要切分支」——查阅照样允许 `git fetch`、部分克隆按需取对象、构建、跑测试、在临时目录写中间文件；
   - 确需在同一仓库并行改两处：指令让新 `worker` 用 `git worktree add <新目录> <基线分支>` 在独立工作树里改，并在笔记里记下谁在哪个目录；
   - 跨项目的冲突由 `desk` 在两份任务书里定分工或先后（它看得见整棵树）。
4. **叶节点动刀前验现场，冲突先上报再等待**：尾部事实只是唤醒那一刻的快照，主人在 IDE 里的手改内核也看不见；所以 `worker` 在第一次改动前必验现场，遇到任何意外即停手上报父节点（或 `desk`）并 `wait`，绝不 `reset / clean / stash / checkout -f` 覆盖他人现场——规则与裁决分工见 `P-SAFE-3`。

### `P-SAFE-3`：主人现场神圣不可侵犯与全角色不可逆操作红线
1. **动刀前必验现场**：任何分身在第一次改动文件、分支或索引（编辑、提交、切换/新建分支、rebase、merge）之前，必须先执行 `git status --short --branch`（目录是 Git 仓库时），并参考尾部「同一工作树里还有谁在干活」的提示：
   - 现场干净，或恰好是任务说明里交代的样子（上一棒留下的分支与改动）：照常动手；
   - 若撞见交接说明之外的**未提交改动、陌生分支、进行中的 rebase / merge 或锁文件、干活时文件在手下被他人改动、或非自身引入的公共构建 / CI 失败**，**绝对禁止擅自执行 `git reset --hard`、`git clean`、`git checkout -f`、`git restore` 或 `git stash`，也不得顺手“修好”它**；
   - 必须立即停手：把目录、当前分支、`git status` 输出（或失败的 CI 任务与报错）、自己的任务与继续所需发给父节点 `inbox:<parentId>`（明显不属于本项目的公共阻塞或无人认领的改动直接发 `inbox:desk`），再以同一地址 `wait` 结束本轮；被答复唤醒后重新检查现场，再严格照答复办。主人（或其外部主 Agent）直接发给该分身的消息本身就是答复，同时了结它对父节点的等待。
   - **裁决分工**：项目内部的事由该 `project` 答复（这是上一棒的分支、该留在哪个分支、等一等还是另开 `git worktree`）；跨项目的冲突与公共阻塞由 `desk` 裁决（同一公共阻塞只派一个修复者，修好后逐一通知所有等待者）；**无人认领的未提交改动一律视为主人正在手写的工作**——`desk` 只能弹出阻塞升级卡（等你提交完再继续 / 你自己 stash 后继续 / 让分身另开目录做）交主人定夺，任何角色都不得指示覆盖。每一个上报冲突并在等待的分身都必须得到答复，绝不晾死。
2. **全角色不可逆操作禁令**：未经人类通过审批卡针对该次具体操作明确点确认，任何角色严禁强推覆盖（`push --force`）、直推或删除受保护主干、删除远端分支/Tag/MR、触碰生产数据库或线上配置、公开发布包或对外群发不可撤回写请求。

## 二、权限、身份与版本并发护栏

### `P-SAFE-4`：单调权限收紧（`child ⊆ parent`）与双身份硬隔离（`owner` vs `agent:*`）
1. **权限沿监督树单调递减**：派生子 `Cell` 时，`Gate.attenuate` 强制保证工具集、可投递地址集与密钥白名单满足 `child ⊆ parent`，且剩余派生深度 `maxDepth` 逐层递减归零即止。
2. **外部主 Agent 编排同权但绝不冒充主人**：
   - 外部主 Agent 通过独立凭证以一等身份 `agent:<id>` 接入控制面，拥有立项、派单、带话、暂停/恢复/取消、勾选人类已完成动作与代办普通计划卡片的完整编排权；
   - **三类确认卡只允许主人批准执行**。向非主人地址发信、预算耗尽后加额续费、批准 `project.start` 立项确认卡都要求 `owner`。外部主 Agent 可依卡片选项推迟、拒绝或要求修改。发起新项目和主人显式开启的常设信任规则遵循 `P-UX-7`。关闭预算限制另受 `P-SAFE-7` 的主人身份校验。

### `P-SAFE-5`：双版本号精确防呆（`Cell.epoch` 防诈尸 + `Artifact.version` 防覆盖与盲发）
1. **`Cell.epoch`**：取消或关闭 `Cell` 时原子递增纪元号；迟到的旧定时器、旧子分身回执或残留后台 `Job` 结果因 `expectedEpoch` 不匹配被内核静默丢弃，彻底杜绝已关项目“诈尸”。
2. **`Artifact.version`**：
   - 跨 `Cell` 修订已有 `Artifact` 强制校验读取时的 `expectedVersion`；若期间人类已在专注区手动改稿提交（`updatedBy: "human"`），后台旧基线写入绝不覆盖手写稿，而是安全旁路暂存（`park`）供参考；
   - 人类点击审批卡确认外发时，同步事务强制校验点击瞬间所见的 `seenArtifactVersion`——若后台刚刷新了新版初稿，立即提示重审，绝不盲发未看过的新内容。

## 三、算力账本、防悬空与宿主电源韧性

### `P-SAFE-6`：5 锚点球权不变量与单次防自激停滞巡检
- 任何处于活跃态（`lifecycle === "active"` 且未 `paused`）的项目及其子树，在任意时刻必须至少拥有以下 **5 类推进锚点**之一：① 在跑的非巡检 `Run / Job` 或待领唤醒消息（`@Agent`）；② 活跃外部监听 `watches / reply_watcher` 或未到期定时调度（`@Waiting: external`）；③ 有明确后继的内部等待，等待 desk 时须有与该项目显式关联的卡、消息或修复者（`@Waiting: internal`）；④ 待批卡片或未完结的 `@Human` 动作（`@Human`）；⑤ 已显式停靠/暂停/完结。处于待命态的 `worker` 不构成任何锚点——它不会自己动，项目必须另有推进者。
- 一旦 5 锚皆空掉入悬空态（`stalled`），`Radar` 立即标红，且内核仅投递**唯一一次** `kernel.stalled_check` 唤醒（巡检消息及其触发的 `Run` 本身不计入有效锚点，彻底杜绝空转死循环烧钱）。

### `P-SAFE-7`：零丢信封的精准增量预算护栏与宿主休眠保护
1. **认领前挂起，零吞入站消息**：`Dispatcher` 在认领任何信封之前先读预算账本——`llm` 处理器的 `Cell` 若自身或任一祖先已到硬上限，就**不启动 `Run`、不认领任何信封**：入站信封（尤其是子分身交回的 `cell.result`）原样留在 `pending` 队列，同时提起一张预算升级卡（每事项至多一张；被挂起期间又有新消息到达时重新提起，主人关掉的卡会回来，绝不让它静默卡死）；续费后它在一轮里拿到挂起期间到达的全部消息。若某个 `Run` 在首次计量前就被拦停、且没有产出任何文本或工具调用，其批次原样退回队列（不计失败次数）并继续挂起。`code` 处理器不花钱，不被挂起。
2. **协调器收尾缓冲**：非根、非叶的协调器在名下没有任何在途工作（无在跑 `Run`、无待领唤醒消息、无运行中 `Job`；被预算挂起的子节点不算在途）时，这一轮可越过链上每个上限一段收尾额度——上限的 5%，且最多 200k tokens / 200 美分——用来记下结果、停靠或结项；越过「上限 + 缓冲」照常拦停。叶节点与根节点没有收尾缓冲。
3. **真实单轮增量与缓存加权计量**：CLI 以会话累计值上报用量时，驱动只计本轮相对已结算累计值的差值（累计值回落即会话重建，此时整段计为新增），杜绝 `resume` 会话的 $O(K^2)$ 重复累加虚增；前缀缓存读取（`cachedTokens`）按 `Gate` 的 `cacheReadWeight`（默认 `0.1`）折算计入 token 上限，原始数字保留在 `usage_log`。
4. **祖先链一键联调续费，余额不静态焊死**：在预算卡上点一次「继续」，`Gate` 沿该 `Cell` 至树根逐个检查，**此刻**处于硬上限的账本一并加额（默认加其上限的一半，且至少足以脱离硬上限），未触顶的不动——绝不背靠背连弹多张预算卡，在兄弟节点的卡上再点一次也不会给共享祖先重复加额。派生子 `Cell` 时不把父节点当时的余额冻结为子上限：子节点始终按整条祖先链的实时账本计量，主人事后追加的额度立即可用。续费与加额仅限人类 `owner`（`P-SAFE-4`）。
5. **预算限制总开关只属于主人**：第 1、2、4 条在预算限制开启（默认）时生效。主人可以整体关闭预算限制——关闭后没有任何 `Cell` 因 token / 费用额度被预警、拦停、挂起或拒绝，也不再提起预算卡；用量照常计量并展示。这是比给单个账本加额更宽的授权，因此与续费同属人类 `owner` 专属决定：`agent:*` 与 `Cell` 调用一律以 `bounds_violation` 拒绝，控制面不提供对应工具。开关可在启动时设定（`KernelOptions.budgetLimits`，工作台以环境变量 `NG_BUDGET_LIMITS=off|on`），也可运行时在工作台切换（`PUT /api/settings/budget-limits`），记在 `<dataDir>/settings.json` 里跨重启保留。关闭的瞬间，所有待处理的预算卡以「继续」作答（不加任何额度），被挂起的 `Cell` 随即启动；重新开启后从下一次判定起恢复拦截。
6. **宿主电源守护与时钟跳变续租**：后台存在活跃 `Run` 或在途任务时，在支持的宿主系统（如 macOS `caffeinate -i`）自动持有防空闲休眠断言；当笔记本合盖物理休眠唤醒、检测到挂钟跳变远大于单调时钟推进时，**必须先顺延所有活跃认领租约（Lease）再执行过期回收扫描**，防止将仍在正常运行的 CLI 进程误判超时重发。

### 受控入口与送达核实

Web 与 MCP 的写命令携带已认证操作者。只有主人能批准已经弹出的外发、加额、立项确认卡或开启常设规则。外部助手可以推迟、拒绝或要求修改。提交校验所见卡片及草稿版本，实际目标与额度由服务端呈现。主人直接要求立项和主人开启的常设信任沿原有规则执行。对外发送在登记意图后进行，迟到的结果按尝试序号核对。送达未知的卡保留到主人核实。

# 长周期多路并行研发与冷恢复

主人交办一个跨模块的大型改造项目：先并行调研与设计，确认方向后在独立工作树里多路实现、后台编译验证、独立复核，并经历跨多轮上下文压缩与会话冷恢复。该场景把真实跨夜长跑中的多路并发、大文稿、后台任务、目录切换与状态恢复串成完整回归。

本机替身：[fixtures/uc09.sh](fixtures/uc09.sh)（带无关 `AGENTS.md` 与路径软链的 `host-trap` 宿主目录、含三模块缺陷与非交互 `stdin` 脚本 `verify_manifest.py` / 静默 CPU 脚本 `bench_heavy.py` / 轮询陷阱脚本 `poll_mr_ci.sh` 的 `catalog-sync` 仓库及本机 `forge` 远端）。

## 行为约定

**`INV-UC09-01`　自然收尾与零冗余等待**　项目派发多个分身、分身启动 `job_start` 后均直接自然结束回合，不调用无对象的裸 `wait`，也不重复登记对自家子分身或自家后台任务的 `wait`。全过程不出现因收尾宽限超时导致的 `<turn_aborted>` 污染或裸 `"OK"` 写入可见记录；仅跨节点发问/仲裁、显式超时或无问号等主人答复才登记等待，且不强迫额外收尾回合。

**`INV-UC09-02`　多路并行交付与大文稿防踩踏**　3–4 个分身并行调研或实现时，各自保存独立模块交付件或汇报结果，由协调器或汇总分身整合为一份面向主人的精炼主报告，不出现多方并发踩踏同一文稿。主报告超过 12 KB 时，`read_artifact` 支持分页与目录查看并直接返回结构化版本号，不倒扣至 4 KB；若发生版本冲突，错误结果只返回当前版本与概要而不倾倒整篇长正文。

**`INV-UC09-03`　目录迁移、并发只读与队友任务可观测**　项目从只读调研切入独立 `git worktree` 实施（`update_project({ cwd })`）并复用已有分身时，通过 `update_cell({ cwd })` 同步更新复用分身的工作目录，使新工作树的技能与目录占用事实生效。复核分身在同一工作树执行只读 git 检查时不与写入分身发生 `index.lock` 冲突；同项目内分身可只读 `job_observe` 队友后台任务，而 `job_input`/`job_cancel` 保持启动者私有。

**`INV-UC09-04`　长历史游标、压缩摘要与冷恢复保真**　分身跨多轮产出大量记录导致 `inspect_cell` 中间省略后，协调器继续按新 `afterSeq` 检视仍将拉取游标推进到高水位 `toSeq`，不持续注入假未读。多次内核压缩后，`[references]` 仅保留完整合法 ASCII 引用并按整条裁剪（绝不腰斩文稿 ID 产生残片）。项目更新目标并触发会话冷恢复后，首条恢复消息不重复注入过时的第一版 `[original task]`，而是锚定最新项目目标；长生命周期叶分身自存的 `working_note` 正常回注；`read_state` 列表不泄露 `cli:session`/`pull:*` 保留键。

**`INV-UC09-05`　后台长任务与活回合韧性**　后台命令默认 stdin 接 `/dev/null`，读取 stdin 至 EOF 的非交互工具立即完成不死锁；将输出重定向到临时文件但进程组 CPU 持续忙碌的编译/测试超过静默阈值时不误报 `job.warning`，临近 `timeoutMs` 不抢发告警。持续产生工具与文本进展的活回合不被固定墙钟强杀；真正卡死无进展触发空闲超时后走续接接力，不将已推进的旧信封无标记重投。

**`INV-UC09-06`　宿主隔离与原生投递卫生**　工作台在包含无关 `AGENTS.md` 的宿主仓库及软链路径下启动时，主台与信源默认目录隔离在仓库之外，不注入无关项目约束，非主台后台节点不继承宿主 CLI 过时记忆摘要。内置技能按角色过滤，叶节点不展示子代配额。由 `prepareRun` 直接消化的子项目结果正常推进主台投递游标，不反复重投旧结果，且内部接纳见证不泄露进 rollout、`inspect_cell` 或压缩摘要。

## 端到端步骤

1. **宿主污染前提启动**：在带无关 `AGENTS.md` 且存在路径软链的宿主目录下启动工作台（宿主 CLI 目录预置旧记忆摘要） → 核对 `desk` 默认目录在仓库外且 rollout 零外部 `AGENTS.md` / 过时记忆注入。
2. **并行调研与模块交付**：主人交办一个三模块改造需求，先出方案 → 项目并行派 3 个分身（各自产出模块文稿），不调裸 `wait` 自然收尾 → 汇总分身整理出一份 >16 KB 精炼主报告；协调器分页读取 `read_artifact`（核对结构化版本、无 4 KB 悬崖）并交付主人审阅。
3. **转实施、切工作树与复用分身**：主人确认进入实施并调整部分目标 → 项目更新目标与 `cwd` 到新建 `git worktree`，用 `update_cell({ cwd })` 同步复用分身目录 → 核对分身加载新工作树技能、活跃工作目录准确、无旧仓假警告；复核分身在同工作树并发做只读 git 检查不打爆写入锁。
4. **后台任务边界压测**：分身启动 3 类后台任务——① 读 stdin 至 EOF 的非交互命令（立刻成功不死锁）；② 输出重定向到 `/tmp/build.log` 且 CPU 忙碌超过静默阈值的编译任务（不误报 `job.warning`）；③ 同项目另一个分身只读 `job_observe`（成功），尝试 `job_cancel`（被拒并写明归属）。分身在 `job_start` 后直接自然结束回合，不调 `wait` 且不被误结算。
5. **长记录、压缩与冷恢复**：制造单分身长记录触发 `inspect_cell` head+tail 省略，随后再跑一轮由项目按新 `afterSeq` 检视 → 核对拉取游标推进到最新 `toSeq`、零假未读；触发多次内核压缩（含中文标点紧贴文稿 ID）并触发会话冷恢复（例如保存偏好或切换目录） → 核对冷恢复 prompt 仅含最新项目目标（无重复旧 `[original task]`）、`[references]` 零残片、叶分身自存 `working_note` 正常回注、`read_state` 列表不含 `cli:`/`pull:`。
6. **长活回合与空闲看门狗**：以较短空闲阈值驱动一个持续推进超过原墙钟窗口的活回合（不强杀），再驱动一个真正静默卡死的回合触发空闲超时（走续接且不重投已推进旧信封）。
7. **提 MR 与完结游标**：仓库自带技能含 CI 轮询步骤，分身按工作台规则只建 MR 即交付；项目仅派 1 个经过字段校验的脚本 checker，不重复监控；项目结项结果被主台 `prepareRun` 直接消化后，再给主台发新消息 → 核对旧 `cell.result` 不重投、rollout/`inspect_cell`/摘要零内部接纳记录泄露。
